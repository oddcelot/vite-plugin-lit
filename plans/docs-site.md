# Plan: Documentation site with Astro + Starlight

Status: **implemented** (2026-09-17, branch `docs/starlight`)
Branch: `docs/starlight`

## Goal

Give `@oddsquad/vite-plugin-lit` a real documentation site that a developer
can land on from npm or GitHub, install the plugin in two minutes, and then
find the deep material (CSS delivery strategy, Timeline API, limitations)
without scrolling a 470-line README.

Stack pinned to today's latest: **Astro 7.3.3**, **@astrojs/starlight
0.42.1**. Verified compatible with the repo's Vite catalog (Astro 7 needs
`vite ^8.0.13`; `vp toolchain vite` reports the catalog bundles `vite@8.3.0`).

## Design principles

1. **Docs become canonical; the README becomes a front door.** One place to
   edit. The README keeps the pitch, install, and links (step 7).
2. **Task-first, then reference.** Guides answer "how do I ship a shared
   Tailwind sheet to 3000 shadow roots"; Reference answers "what does
   `cssSheetBuild: 'inline-raw'` do". Every reference page links back to
   the guide that motivates it.
3. **Everything in the docs is verified by a build.** Internal links checked
   at build time, code samples typed against the real package via
   `workspace:*`, docs build runs in CI on every PR.
4. **Agent-readable.** Ship `llms.txt` and per-page markdown. Devs using this
   plugin will paste the docs URL into an agent; make that work.
5. **Boring infrastructure.** GitHub Pages, one workflow, no custom theme
   beyond an accent colour and a wordmark.

## Authoring conventions

- `.md` by default; `.mdx` only when a page uses a Starlight component.
- Components allowed: `Tabs/TabItem`, `Steps`, `Aside`, `Card/CardGrid`,
  `LinkCard`, `FileTree`, `Badge`, `Code` (with `mark`/`ins`/`del` for
  before/after config diffs), `PackageManagers` (install tabs).
- Every guide opens with a two-sentence "when you want this" and ends with a
  "Related" `LinkCard` row to the reference page(s).
- Every option in `/reference/options` has an anchor `#hmr-reconnect` style
  so guides can deep-link.
- Code samples use the repo's formatting (single quotes, no bracket spacing)
  so copy-paste matches what `vp fmt` would produce in a consumer's repo.
- No version-specific prose ("since 0.2.3"). No changelog page (none exists).

## Decision notes (made without asking; revisit if wrong)

1. **`docs/` is the site, not `website/`.** `docs/` already exists with one
   markdown file that becomes a page. Astro's convention and GitHub's
   "docs folder" affordance both favour it. The old `docs/css-delivery.md`
   path in README links is the only cost.
2. **Hand-written options reference, no `starlight-typedoc`.** Two reasons:
   the public surface is four options plus two helpers, small enough to
   curate; and `typedoc@0.28` peers on `typescript <= 6.0.x` while the repo
   is on TypeScript 7.0.2, so it would need a second TypeScript in the
   graph. Revisit if the API grows past ~15 exported symbols.
3. **No `@astrojs/check` / `astro check` step.** Same TypeScript peer
   concern, and there is no `.astro` component code to type-check in v1.
   `tsc` in the docs package would only cover `content.config.ts`.
4. **GitHub Pages project page with `base: '/vite-plugin-lit'`.** No custom
   domain is known. If one is added later: set `site`, drop `base`, add
   `public/CNAME`. All internal links must use Starlight's slug/link
   handling so the base change is config-only.
5. **Deploy from `main` on push, gate on PR.** No release-coupled docs
   versioning; the package is 0.x and moves fast. Add versioned docs only
   if a 1.0 breaks config.
6. **Neutral branding, not Lit's.** This is a third-party plugin; reusing
   Lit's palette or logo invites confusion with `@lit-labs`. One accent hue,
   text wordmark, default Starlight otherwise. A proper logo is out of scope.
7. **No embedded live demos.** The playground is already StackBlitz-ready
   (`playground/package.json` has a `stackblitz` block); link to it from
   Quick start and HMR guide instead of embedding iframes that fight the
   `base` path and CSP.
8. **Docs depend on the plugin via `workspace:*`.** Costs nothing now and
   lets a later step import `LitPluginOptions` into a typed `<Code>` sample
   or read the package version at build time.
9. **Vite stays on the catalog alias.** Confirmed version range is fine;
   step 0 is the empirical check. The parent-scoped override is the only
   sanctioned fallback because a second real `vite` in the graph is exactly
   what the existing override was written to prevent.
10. **No "Migrating from @lit-labs/vite-plugin-lit" page yet.** The README
    only states lineage, not deltas. Flagged as a content gap that needs the
    author's knowledge; a short "Relationship to the upstream plugin"
    paragraph goes on the how-it-works page as a placeholder.
11. **No i18n.** Single `en` locale; Starlight's `defaultLocale` is left
    unset so URLs stay unprefixed.
12. **`format` glob gets `mdx`, not `astro`.** oxfmt's `.astro` support is
    unverified and there are no `.astro` files in v1. If prose formatting of
    `.mdx` proves noisy in review, drop `mdx` too and rely on Starlight's
    build for correctness.

## Risks

- **Catalog alias breaks Astro's Vite import paths.** Mitigated by step 0
  and its fallback.
- **oxlint type-aware pass picks up `docs/src/**` with the root tsconfig**
  (which only includes `src/**`). If `vp check` errors on the docs package,
  add a `docs/tsconfig.json`-aware override or ignore `docs/src/**` in lint
  and rely on Astro's build. Decide in step 1, record the outcome here.
- **README/docs drift during steps 2–5.** Until step 5 lands, README is
  still complete; nothing is deleted before the site is live.
- **GitHub Pages must be enabled manually.** The first deploy will fail
  until the owner flips the setting; the plan calls this out.

## Implementation notes (2026-09-17)

Recorded where reality differed from the plan.

1. **Step 0 passed with no fallback.** `astro build` works under the catalog
   alias (`docs/node_modules/vite` resolves to
   `@voidzero-dev/vite-plus-core@0.3.2`); the parent-scoped override was not
   needed. Installing astro did add `esbuild` to the tree, so
   `pnpm-workspace.yaml` gained `allowBuilds: {esbuild: true}` — pnpm 12 blocks
   the install otherwise.
2. **Sidebar groups use `items: [{autogenerate: …}]`.** The sketch's bare
   `autogenerate` key on a group was removed in Starlight 0.39 and is a hard
   error in 0.42.
3. **Internal links carry the `/vite-plugin-lit` base.** Decision note 4 wanted
   the base to be config-only, but Astro does not prefix hrefs written in
   Markdown, and Astro 7's Markdown processor (Sätteri) takes no rehype plugins
   unless you install `@astrojs/markdown-remark` and swap the processor out —
   too much machinery for the problem. A custom-domain move is a find-and-
   replace over `docs/src/content/`, and the links validator (which checks
   anchors as well as pages) fails the build on anything stale.
4. **Guide `sidebar.order` values are spread out (1–9).** Starlight orders an
   autogenerated directory group by the _lowest_ order among its pages, so the
   group positions and the page positions come out of the same sequence.
5. **`format` glob keeps `mdx`.** oxfmt only realigns tables and re-wraps
   prose, with one exception: it mangles the nested-backtick inline-code form
   (` ` css` `). That construct was rewritten rather than dropping `mdx`
   from the glob.
6. **Lint needed no docs override.** The risk about the type-aware pass picking
   up `docs/src/**` under the root tsconfig did not materialize; `vp check`
   passes with only `docs/dist/` and `docs/.astro/` in `ignorePatterns`.
7. **Deploy does not use `withastro/action`.** It would install its own pnpm
   (`package-manager` input) next to a pnpm 12 lockfile and the repo's corepack
   pin. The workflow instead mirrors `ci.yaml` (corepack, Node 26,
   `--frozen-lockfile`) and hands `docs/dist` to `actions/upload-pages-artifact`
   - `actions/deploy-pages`. The build job runs on PRs and on `main`; only
     `main` deploys.
8. **Step 5 landed on the same branch**, as its own commit rather than a
   separate PR.
