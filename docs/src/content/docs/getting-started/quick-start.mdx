You want this the first time you add the plugin: one config change, one edit,
and a way to tell whether a save was hot-patched or silently reloaded the page.

## Add the plugin

```ts
// vite.config.ts
import {defineConfig} from 'vite';
import {litPlugin} from '@oddsquad/vite-plugin-lit';

export default defineConfig({
  plugins: [litPlugin()],
});
```

That is the whole setup. HMR, the on-page indicator, and the CSS import
queries are on by default; the DevTools timeline and the source overlay are
opt-in.

The HMR feature only applies to the dev server (`apply: 'serve'`); production
builds are untouched. The CSS queries (`?hmr-url`, `?css-sheet`) and Lightning
CSS literal processing apply in both dev and build.

## Make your first edit

<Steps>

1. Start the dev server and open a page that renders a Lit component.

2. Type into an input inside that component, or scroll a list it owns — give
   it some state worth losing.

3. Edit the component's template: change a label, add a class, tweak the
   markup around the part you interacted with.

4. Save. The component's DOM updates, the focus, selection, and scroll
   position stay exactly where they were, and the indicator in the corner of
   the page pulses green.

</Steps>

If instead the whole page reloads, the edit hit one of the cases that cannot
be patched in place — see [Limitations](/vite-plugin-lit/reference/limitations/)
for the full list and how to tell which one fired.

<Aside title="Try it without installing anything">
  The repository ships a [playground
  app](https://github.com/oddcelot/vite-plugin-lit/tree/main/playground) that is
  self-contained enough to open on StackBlitz straight from the repo URL. It is
  also the source for the e2e fixtures, so it exercises every delivery mode
  documented here.
</Aside>

## What the indicator counts

The injected indicator (`hmr.indicator`, with `hmr.indicator.count` for the
running total) counts only updates that actually **re-render a component**. A
pure shared-stylesheet hot-swap restyles adopted sheets in place without
re-rendering, so it pulses in the calmer info color and leaves the count
untouched; a per-element `.css` or any component-module edit both re-renders and
counts (green pulse). A non-accepted edit (e.g. `main.ts`) falls back to a full
reload, which remounts everything and resets the count.

| Playground edit         | Delivery                  | Re-renders? | Counts? | Pulse           |
| ----------------------- | ------------------------- | ----------- | ------- | --------------- |
| `hmr-vsheet.css`        | `?css-sheet` shared sheet | no          | no      | info (cyan)     |
| `hmr-shared.css`        | `?raw` → shared sheet     | no          | no      | info (cyan)     |
| `hmr-utility-sheet.css` | `?url` → shared sheet     | no          | no      | info (cyan)     |
| `hmr-linked-css.css`    | `?hmr-url` `<link>`       | yes         | yes     | success (green) |
| `hmr-import-css.css`    | `?hmr-url` `@import`      | yes         | yes     | success (green) |
| `hmr-css-url.css`       | `?url` + `devCacheBust()` | yes         | yes     | success (green) |
| `hmr-raw-css.css`       | `?raw` static styles      | yes         | yes     | success (green) |
| any `*.ts` component    | component module          | yes         | yes     | success (green) |
| `main.ts`               | not self-accepting        | full reload | resets  | —               |
