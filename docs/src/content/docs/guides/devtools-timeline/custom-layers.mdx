You want this when your app has its own events worth lining up against Lit's —
a router navigation, a websocket message, a store commit — and you would rather
see them on the same time axis than in the console.

## Register a layer, emit events

App code and other plugins can emit events on custom layers:

```ts
import {addTimelineEvent, addTimelineLayer} from 'virtual:lit-plugin/timeline';

// Register once (idempotent)
addTimelineLayer({id: 'my-layer', label: 'My Events', color: 0xff6b35});

// Emit from anywhere in the app
addTimelineEvent({
  layerId: 'my-layer',
  time: performance.now(),
  title: 'something happened',
  data: {detail: 42},
});
```

The virtual module resolves to a no-op stub in production and when `timeline`
is disabled, so imports are safe to leave in component code.

`color` is a number, not a CSS string — `0xff6b35` rather than `'#ff6b35'`.
`data` is whatever you want the event's detail pane to show; it is serialized,
so keep it to plain values.

<Aside type="caution" title="No ambient types yet">
  `virtual:lit-plugin/timeline` has no ambient declaration, so TypeScript
  reports `TS2307: Cannot find module`. The [import queries
  reference](/vite-plugin-lit/reference/import-queries/#virtuallit-plugintimeline)
  has the `declare module` workaround to use until it ships.
</Aside>
