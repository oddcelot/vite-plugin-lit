Point at any element on the page and jump to the file and line that renders
it. Off by default; one option turns it on.

## Turn it on

```ts title="vite.config.ts"
import {defineConfig} from 'vite';
import {litPlugin} from '@oddsquad/vite-plugin-lit';

export default defineConfig({
  plugins: [litPlugin({sourceOverlay: true})],
});
```

Prefer to leave the config alone? Every option also reads from the
environment, so a personal `.env.local` works just as well.

```ini title=".env.local"
LIT_PLUGIN_SOURCE_OVERLAY=true
LIT_PLUGIN_SOURCE_OVERLAY_EDITOR=zed
```

<Aside type="caution" title="Dev only">
  The overlay, its middleware and its injected runtime exist only on the dev
  server. Nothing about it reaches a production build.
</Aside>

## Use it

<Steps>

1. Press **Ctrl+Shift+S** (**⌘⇧S** on a Mac) in the page to arm the picker.

2. Move the pointer. The element under it is outlined, and a panel shows its
   tag name and source file.

   <ThemedImage
     light={sourceOverlayArmedLight}
     dark={sourceOverlayArmedDark}
     alt="The source overlay outlining a component, with a tooltip showing its tag name and source file."
   />

3. Hold **Ctrl** (or **⌘**) and click the element to open that file in your
   editor at that line. The tooltip's own **open** button does the same.

4. Press the same keys again to put the picker away without opening anything.

</Steps>

A plain click, without the modifier, hands the element to the DevTools
Components tab instead, when the panel is set up. The tooltip also carries a
**copy** button for the `file:line` pair, for pasting into an issue.

## Choose your editor

The built-in keys are `vscode` (the default), `cursor`, `zed`, `idea` and
`windsurf`. An unknown key falls back to VS Code.

```ts title="vite.config.ts"
import {defineConfig} from 'vite';
import {litPlugin} from '@oddsquad/vite-plugin-lit';

export default defineConfig({
  plugins: [litPlugin({sourceOverlay: {editor: 'zed'}})],
});
```

Anything else is a `{name, url}` pair. The `url` function receives the
absolute path and the line number, and returns the URL to open.

```ts title="vite.config.ts"
import {defineConfig} from 'vite';
import {litPlugin} from '@oddsquad/vite-plugin-lit';

export default defineConfig({
  plugins: [
    litPlugin({
      sourceOverlay: {
        editor: {
          name: 'My Editor',
          url: (path, line) => `my-editor://open?file=${path}&line=${line}`,
        },
      },
    }),
  ],
});
```

Opening normally goes through a dev-server middleware and falls back to the
editor's URL scheme when the server is unreachable, as in a StackBlitz
preview. [DevTools architecture](/vite-plugin-lit/concepts/devtools-architecture/)
explains why, and why the DevTools panel's own source links take a different
route.

## Change the shortcut and other options

```ts title="vite.config.ts"
import {defineConfig} from 'vite';
import {litPlugin} from '@oddsquad/vite-plugin-lit';

export default defineConfig({
  plugins: [
    litPlugin({
      sourceOverlay: {
        key: 'i',
        throttleMs: 50,
        workspaceRoot: '/Users/me/projects/app',
        exclude: (el) => el.tagName.startsWith('MY-INTERNAL-'),
        onSelect: (info) => console.log(info.tagName, info.source.filePath),
      },
    }),
  ],
});
```

- `key` is the letter combined with Ctrl+Shift, so `'i'` gives Ctrl+Shift+I.
  Defaults to `'s'`. Avoid `'e'`: it collides with the panel's Meta+Shift+E pick shortcut.

- `throttleMs` throttles pointer-move hit testing. Defaults to `50`.
- `workspaceRoot` prefixes source paths, for when your editor needs absolute
  ones. Unset by default.
- `exclude` returns `true` for elements the picker should skip.
- `onSelect` fires with the picked element's info. The default action still
  runs after it.

The picker is shared: the DevTools Components tab reuses it for its **Pick**
button, so element picking there needs `sourceOverlay` enabled too.
